\chapter{Computer Vision}
\label{sec:vision_pipeline}

To enable closed-loop alignment of the gantry end-effector to objects on the conveyor, a computer vision pipeline was developed to estimate each target's pose. Since the gantry operates with a fixed vertical approach and the conveyor height is known, the Z-coordinate is determined by the physical setup rather than estimated from vision. The vision system therefore estimates only the X and Y position and yaw angle ($\theta_z$) --- the three unknown degrees of freedom required for alignment and placement.

The pipeline evolved through two stages during the project. An initial classical pipeline based on HSV thresholding and contour analysis (Section~\ref{sec:classical_pipeline}) was developed in simulation and validated on real hardware, where it exposed fundamental limitations. These motivated a transition to a deep learning--based approach (Section~\ref{sec:dl_pipeline}) using keypoint regression and Perspective-n-Point (PnP) pose recovery, which provides metric-space pose estimation and greater robustness to appearance variation.

\section{Classical Pipeline}
\label{sec:classical_pipeline}

The initial pipeline, illustrated in Figure~\ref{fig:vision_pipeline_flow}, uses OpenCV to segment the target object, remove noise, and estimate its 2D pose in the image frame.

\begin{figure}[H]
    \centering
    \includegraphics[width=\linewidth]{figures/vision_pipeline.png}
    \caption{Classical vision pipeline for segmentation and pose estimation using HSV thresholding, morphological filtering, contour extraction, and minimum-area rectangle fitting.}
    \label{fig:vision_pipeline_flow}
\end{figure}

The captured image is converted to HSV colour space so that the processing remains robust to changes in lighting intensity. Binary masks are generated using thresholding: the black object mask is thresholded primarily on the Value channel for dark region isolation, while the brown object mask uses a constrained HSV range tuned for the brown colour of cardboard boxes. This allows the pipeline to detect objects of specific colours without resorting to data-hungry deep learning techniques.

Small artifacts in the binary mask are cleaned with standard morphological operations: closing to fill small gaps and opening to remove isolated noise, using a $5 \times 5$ structuring element with multiple iterations as needed.

External contours are found using \texttt{cv2.findContours(..., RETR\_EXTERNAL)}. The pipeline extracts the contour with the greatest area; all other contours are rejected as false detections. The selected contour is fit using \texttt{cv2.minAreaRect}, yielding:
\begin{itemize}
    \item Centre in pixels: $(u, v)$
    \item Rectangle dimensions: $(w, h)$
    \item Raw angle: $\theta_{\text{raw}}$
\end{itemize}

OpenCV's angle convention depends on the longer edge, so the raw angle is normalised to supply a consistent orientation $\theta \in [0, 180)$.

\subsection{Image-Based Visual Servoing Formulation}

For closed-loop control, an IBVS formulation was selected because it operates directly on pixel coordinates, eliminating the need for a calibrated camera-to-world transformation. For a feature vector $s = [x \;\; y \;\; \theta]^T$, the control objective is to reduce the error:
\[
e = s - s^{*}
\]
where $s$ is measured from the current camera frame and $s^{*}$ is the desired feature (target centred in the image with desired yaw). The pixel coordinates $(u, v)$ are converted to normalised image coordinates:
\[
x = \frac{u - c_x}{f_x}, \quad y = \frac{v - c_y}{f_y}
\]
and the interaction matrix $L_s$ maps camera velocities to feature motion:
\[
\dot{s} = L_s \, v
\]
The standard IBVS control law is then:
\[
v = -\lambda \, L_s^{+} \, e
\]
where $\lambda > 0$ is a gain and $L_s^{+}$ is the pseudo-inverse of the interaction matrix. This allows closed-loop alignment using only camera measurements, without requiring the object's pose in world coordinates.

\subsection{Real-World Validation}

The classical pipeline was tested on a real Dawlance microwave and its corresponding box. Orientation estimation was accurate to within half a degree. However, position estimation exhibited errors caused by the open flaps of the box and the protruding edges of the microwave, which distorted the contour shape and shifted the computed centre.

\section{Limitations of Classical Pipeline}
\label{sec:classical_limitations}

While the HSV-based pipeline demonstrated reliable performance in simulation, deployment on real hardware exposed several fundamental limitations:

\begin{enumerate}
    \item \textbf{Colour dependency:} HSV thresholding required manual tuning of per-object colour ranges. Any change in object appearance, conveyor background, or lighting conditions necessitated recalibration.
    \item \textbf{Single-class limitation:} Each colour range was hand-tuned for one object type. Extending the pipeline to new objects required defining additional masks, with no principled way to handle objects sharing similar colour profiles.
    \item \textbf{No metric pose:} The \texttt{minAreaRect} fit provided only a 2D centre $(u, v)$ and an in-plane angle $\theta$. While sufficient for IBVS, this precluded position-based control strategies that require the object's position in world coordinates.
    \item \textbf{No semantic keypoints:} The contour-based approach had no notion of specific object features (e.g., corners of the top face). Without known correspondences between image points and physical geometry, camera-to-object distance and full 6-DoF pose could not be recovered.
\end{enumerate}

These limitations motivated a transition from classical image processing to a deep learning--based approach capable of jointly detecting objects, classifying them, and localising semantically meaningful keypoints in a single forward pass.

\section{Deep Learning--Based Pose Estimation Pipeline}
\label{sec:dl_pipeline}

To address the shortcomings identified in Section~\ref{sec:classical_limitations}, the vision pipeline was redesigned around a keypoint-based pose estimation architecture. The revised pipeline, illustrated in Figure~\ref{fig:dl_pipeline_flow}, replaces HSV thresholding, morphological filtering, and contour extraction with a single neural network that simultaneously performs object detection (bounding box and class) and keypoint regression. The detected keypoints, corresponding to known physical corners of the target object, are then passed to a Perspective-n-Point (PnP) solver to recover the full 6-DoF pose relative to the camera.

\begin{figure}[H]
    \centering
    \includegraphics[width=\linewidth]{figures/dl_vision_pipeline_flowchart.pdf}
    \caption{Revised vision pipeline using YOLOv26n-pose for joint detection and keypoint regression, followed by PnP-based 6-DoF pose estimation.}
    \label{fig:dl_pipeline_flow}
\end{figure}

This design offers three key advantages over the classical approach. First, the network learns appearance-invariant features from data, eliminating manual colour tuning and providing robustness to lighting variation. Second, the architecture natively supports multiple object classes --- in this case, microwaves and their packaging boxes --- within a unified model. Third, by regressing semantically defined keypoints (the four top-face corners), the pipeline establishes the 2D--3D correspondences required for metric pose recovery via \texttt{cv2.solvePnP}, enabling position-based control strategies alongside or in place of IBVS.

\section{Keypoint Definition}
\label{sec:keypoint_def}

The choice of keypoints is driven by two constraints: they must be consistently visible from the overhead camera, and they must form a known planar geometry so that \texttt{cv2.solvePnP} can recover pose from a minimum of four 2D--3D correspondences. Because both the microwave and the cardboard package present a flat, roughly rectangular top face to the camera, the four corners of this face are selected as the keypoint set:

\begin{enumerate}
    \item \textbf{TFL} --- Top Front Left
    \item \textbf{TFR} --- Top Front Right
    \item \textbf{TBL} --- Top Back Left
    \item \textbf{TBR} --- Top Back Right
\end{enumerate}

\begin{figure}[H]
    \centering
    \includegraphics[width=0.75\linewidth]{figures/key-points.png}
    \caption{Keypoint convention for both object classes. TFL, TFR, TBL, and TBR denote the four corners of the top face as seen from the overhead camera.}
    \label{fig:keypoint_def}
\end{figure}

Since both classes share the same four-keypoint layout, a single model head can regress keypoints for all detections regardless of class. The keypoint ordering defines a left--right mirror symmetry: under horizontal flip, TFL swaps with TFR and TBL swaps with TBR, encoded via the \texttt{flip\_idx: [1, 0, 3, 2]} field in the dataset configuration.

Each keypoint is stored in the YOLO pose format as a triplet $(x, y, v)$, where $x$ and $y$ are normalised image coordinates and $v \in \{0, 1, 2\}$ is a visibility flag (0~=~absent, 1~=~occluded, 2~=~visible). A label row thus contains 17 values: 5 for the bounding box (class, $c_x$, $c_y$, $w$, $h$) and $4 \times 3 = 12$ for the keypoints.

\section{Dataset Preparation}
\label{sec:dataset_prep}

The training dataset was assembled by merging three separate annotation efforts, each created at a different stage of the project:

\begin{enumerate}
    \item \textbf{Old dataset:} 8-keypoint COCO-format annotations for microwaves only. Only the top four keypoints (indices 0--3) were retained during conversion.
    \item \textbf{Mid dataset:} 4-keypoint YOLO-format annotations for microwaves only, already conforming to the top-face convention.
    \item \textbf{New dataset:} 4-keypoint YOLO-format annotations with two classes: microwave (class~0) and package (class~1).
\end{enumerate}

A format-conversion script was written to: \textit{(i)}~extract only the top-four keypoints from the old dataset by index, \textit{(ii)}~convert bounding boxes from COCO absolute $(x, y, w, h)$ to YOLO normalised centre format, and \textit{(iii)}~assign the class ID to~0 (microwave). The mid and new datasets, already in YOLO pose format, were copied directly with class IDs preserved. All images and labels were merged into a single directory structure with unique filename prefixes (\texttt{old\_}, \texttt{mid\_}, \texttt{new\_}) to prevent collisions.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.85\linewidth]{figures/dataset_merge_pipeline.pdf}
    \caption{Dataset curation pipeline. Three annotation sources are converted to a unified YOLO pose format with 2 classes and 4 keypoints per instance.}
    \label{fig:dataset_merge}
\end{figure}

The final merged dataset configuration is specified in a YAML file consumed by the Ultralytics training API:

\begin{verbatim}
nc: 2
names:
  0: microwave
  1: package
kpt_shape: [4, 3]
flip_idx: [1, 0, 3, 2]
\end{verbatim}

\section{Model Architecture and Training}
\label{sec:model_training}

The detection and keypoint regression model is YOLOv26n-pose, a nano-variant of the YOLO architecture optimised for real-time pose estimation. The model accepts a $640 \times 640$ input image and produces, for each detected object, a bounding box with class confidence and a set of $K = 4$ keypoint coordinates with per-keypoint confidence scores.

Training was initialised from the official \texttt{yolo26n-pose.pt} pretrained weights and fine-tuned on the merged dataset for 150 epochs with the hyperparameters listed in Table~\ref{tab:training_params}.

\begin{table}[H]
    \centering
    \caption{YOLOv26n-pose training hyperparameters.}
    \label{tab:training_params}
    \renewcommand{\arraystretch}{1.2}
    \begin{tabular}{@{}ll@{}}
        \toprule
        \textbf{Parameter} & \textbf{Value} \\
        \midrule
        Input size         & $640 \times 640$ \\
        Batch size         & 8 \\
        Epochs             & 150 \\
        Pretrained weights & \texttt{yolo26n-pose.pt} \\
        Flip LR / Flip UD  & 0.0 / 0.0 \\
        Mosaic / MixUp     & 0.0 / 0.0 \\
        Rotation / Perspective / Shear & 0.0 / 0.0 / 0.0 \\
        \bottomrule
    \end{tabular}

All geometric augmentations were disabled. While standard for object detection, these augmentations can corrupt keypoint semantics in pose estimation tasks. Mosaic and mixup composite multiple images, potentially splitting an object's keypoints across tile boundaries. Large rotations and perspective warps alter the spatial relationship between keypoints in ways that the fixed \texttt{flip\_idx} mapping cannot account for. Since the gantry camera always views the conveyor from roughly the same overhead angle, the limited viewpoint variation in deployment further reduces the need for geometric augmentation.

\section{Camera Calibration}
\label{sec:camera_calib}

The wrist-mounted AR0234 camera uses a fisheye lens to maximise the field of view over the conveyor. Fisheye lenses introduce significant radial distortion, particularly near the image periphery, which displaces pixel coordinates from their ideal pinhole-model positions. If uncorrected, this distortion degrades the accuracy of the PnP pose estimate.

Camera calibration was performed offline using an ArUco marker board, yielding two outputs:

\begin{itemize}
    \item The \textbf{intrinsic matrix} $\mathbf{K}$, containing the focal lengths $(f_x, f_y)$ and principal point $(c_x, c_y)$:
    \[
    \mathbf{K} = \begin{bmatrix} f_x & 0 & c_x \\ 0 & f_y & c_y \\ 0 & 0 & 1 \end{bmatrix}
    \]
    \item The \textbf{distortion coefficients} $\mathbf{d} = [k_1, k_2, p_1, p_2, k_3, \ldots]$, modelling radial and tangential lens distortion.
\end{itemize}

These parameters are stored in a NumPy archive and loaded at inference time. The YOLO model runs on the raw distorted image; undistortion is deferred to the PnP stage, where the distortion coefficients are passed directly to \texttt{cv2.solvePnP}. This avoids the computational cost of undistorting the full frame at every inference step while still accounting for lens distortion during pose recovery.

\section{PnP-Based 6-DoF Pose Recovery}
\label{sec:pnp_pose}

Given the four detected keypoints in pixel coordinates and the known physical dimensions of each object class, the Perspective-n-Point (PnP) algorithm recovers the 6-DoF pose (rotation $\mathbf{R}$ and translation $\mathbf{t}$) of the object with respect to the camera frame.

\subsection{3D Object Model}

For each class, a planar 3D model is defined by placing the four top-face corners in a local object coordinate frame with the top surface at $Z = 0$:

\begin{table}[H]
    \centering
    \caption{3D object models for PnP. All keypoints lie on the $Z = 0$ plane. Dimensions in metres.}
    \label{tab:object_models}
    \renewcommand{\arraystretch}{1.2}
    \begin{tabular}{@{}lcccc@{}}
        \toprule
        \textbf{Class} & \textbf{TFL} & \textbf{TFR} & \textbf{TBL} & \textbf{TBR} \\
        \midrule
        Microwave & $(0, 0, 0)$ & $(0.44, 0, 0)$ & $(0, 0.61, 0)$ & $(0.44, 0.61, 0)$ \\
        Package   & $(0, 0, 0)$ & $(0.57, 0, 0)$ & $(0, 0.67, 0)$ & $(0.57, 0.67, 0)$ \\
        \bottomrule
    \end{tabular}
\end{table}

\subsection{Solver Configuration}

The PnP problem is solved using a two-stage fallback strategy. The primary solver is \texttt{SOLVEPNP\_IPPE} (Infinitesimal Plane-based Pose Estimation), designed for coplanar point configurations, which returns up to two candidate poses. If IPPE fails due to near-degenerate keypoint configurations, the solver falls back to \texttt{SOLVEPNP\_ITERATIVE}, which uses Levenberg--Marquardt refinement from a DLT initial estimate.

The solver receives the 3D model coordinates from Table~\ref{tab:object_models}, the four keypoint pixel coordinates from the YOLO prediction (filtered by a per-keypoint confidence threshold of 0.30), and the camera matrix $\mathbf{K}$ and distortion coefficients $\mathbf{d}$ from calibration. The outputs are the rotation vector $\mathbf{r}$ (Rodrigues form) and translation vector $\mathbf{t}$.

\subsection{Pose Interpretation}

From the recovered pose, two distance measures are computed:
\begin{enumerate}
    \item \textbf{Distance to object origin:} $d_{\text{origin}} = \|\mathbf{t}\|$, the Euclidean distance from the camera to the TFL corner.
    \item \textbf{Distance to object centre:} The 3D centre of the top face, $\mathbf{p}_{\text{obj}} = [W/2, \; D/2, \; 0]^T$, is transformed to camera coordinates via $\mathbf{p}_{\text{cam}} = \mathbf{R}\,\mathbf{p}_{\text{obj}} + \mathbf{t}$, and the distance is $d_{\text{centre}} = \|\mathbf{p}_{\text{cam}}\|$.
\end{enumerate}

\subsection{Reprojection Error}

To assess the quality of each pose estimate, the 3D model points are reprojected into the image using the recovered $\mathbf{r}$ and $\mathbf{t}$:
\[
\hat{\mathbf{p}}_i = \texttt{projectPoints}(\mathbf{P}_i, \mathbf{r}, \mathbf{t}, \mathbf{K}, \mathbf{d})
\]
The mean reprojection error is:
\[
e_{\text{reproj}} = \frac{1}{4} \sum_{i=1}^{4} \| \hat{\mathbf{p}}_i - \mathbf{p}_i \|_2
\]
where $\mathbf{p}_i$ are the detected keypoints and $\hat{\mathbf{p}}_i$ are their reprojections. A low reprojection error (typically $< 5$\,px) indicates a geometrically consistent pose. This metric serves as an online quality gate: detections with high reprojection error can be rejected before being passed to the gantry controller.

\section{Alternative Pipeline: Grounding DINO + SAM2}
\label{sec:gdino_pipeline}

In parallel with the YOLO26n-pose pipeline, an alternative approach was explored using foundation models that require no task-specific training data. This pipeline combines Grounding DINO~\cite{liu2023grounding} for open-vocabulary object detection with SAM2~\cite{ravi2024sam2} for pixel-level segmentation, followed by the same PnP-based pose recovery described in Section~\ref{sec:pnp_pose}.

The pipeline operates in three stages:
\begin{enumerate}
    \item \textbf{Detection:} Grounding DINO accepts a text prompt (e.g., ``microwave'' or ``cardboard box'') and localises the corresponding object in the camera frame, producing a bounding box without requiring any annotated training images.
    \item \textbf{Segmentation:} The bounding box is passed to SAM2, which generates a precise pixel-level mask of the detected object.
    \item \textbf{Pose estimation:} The bottom edge of the segmentation mask is used to identify the object's base, from which the four top-face corner keypoints are inferred geometrically. These keypoints are then passed to the same PnP solver (Section~\ref{sec:pnp_pose}) to recover position and yaw.
\end{enumerate}

The principal advantage of this approach is its zero-shot capability: because Grounding DINO is prompted with natural language rather than trained on labelled examples, the pipeline can detect new microwave models or packaging variants without any dataset expansion or retraining. This makes it attractive for production deployment, where Dawlance's product range may change over time.

The pipeline was tested with the AR0234 global shutter camera mounted on the prototype. Position estimation achieved an error of approximately 5\% relative to the object's distance from the camera origin. At typical working distances of 1--2\,m, this corresponds to errors of 5--10\,cm, which exceeds the $<1$\,cm positional accuracy specification in Table~\ref{tab:specs}. This error is attributed primarily to camera calibration rather than a fundamental limitation of the detection and segmentation pipeline, and is expected to improve with more rigorous intrinsic and extrinsic calibration. Yaw estimation was qualitatively correct.

The trade-off relative to the YOLO26n-pose pipeline is inference speed: the cascaded Grounding DINO + SAM2 architecture requires significantly more computation than the single-pass YOLO model, making it less suitable for real-time closed-loop control without GPU acceleration. For the prototype, this pipeline was used for offline validation and as a fallback for situations where the YOLO model had not been trained on a particular object.
